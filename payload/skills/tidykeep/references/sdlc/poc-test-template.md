# POC 测试用例格式参考

本文件描述 POC（Proof of Concept）功能测试用例的标准格式，供阶段 6.8 功能测试方案设计使用。

## 标准测试用例结构

每个测试用例必须包含以下字段：

| 字段 | 说明 | 示例 |
|---|---|---|
| 测试项编号 | 唯一标识符，如 T01、T02 | T01 |
| 测试名称 | 简洁描述测试目的 | 用户登录成功 |
| 测试类型 | Web UI / API / CLI / 单元测试 | Web UI |
| 预置条件 | 执行前需准备的环境、数据、权限 | 已注册用户账号，系统运行中 |
| 测试步骤 | 编号列表，具体到操作 | 1. 打开登录页面 2. 输入用户名 3. 输入密码 4. 点击登录 |
| 预期结果 | 每个步骤对应的期望输出 | 登录成功，跳转到首页 |
| 测试结果 | 实际执行后填写：通过 / 失败 / 阻塞 | 通过 |

### Web UI 测试示例

**测试项编号**：T01
**测试名称**：用户登录功能 - 正常登录
**测试类型**：Web UI
**预置条件**：
- 系统已部署并运行
- 已注册测试用户（用户名：testuser，密码：Test@123）

**测试步骤**：
1. 打开浏览器，访问 `http://localhost:3000/login`
2. 在用户名输入框输入 `testuser`
3. 在密码输入框输入 `Test@123`
4. 点击"登录"按钮

**预期结果**：
- 步骤 1：登录页面正常加载，显示用户名和密码输入框
- 步骤 2-3：输入框正确显示输入内容，密码以掩码形式展示
- 步骤 4：页面跳转至首页，显示用户昵称或欢迎信息

### API 测试示例

**测试项编号**：T05
**测试名称**：创建用户接口 - 正常创建
**测试类型**：API
**预置条件**：
- API 服务已启动
- 数据库已初始化
- 具备管理员权限的 API Key

**测试步骤**：
1. 发送 POST 请求至 `/api/users`
2. 请求体包含：`{"username": "newuser", "email": "new@example.com", "password": "Pass@123"}`
3. 携带 Header：`Authorization: Bearer <admin_token>`
4. 检查响应状态码和响应体

**预期结果**：
- 步骤 4：HTTP 状态码为 201
- 响应体包含新创建用户的基本信息（ID、用户名、邮箱）
- 密码字段不在响应体中返回
