# 阶段 8：项目文档维护

**角色**：技术文档工程师
**目标**：汇总技术文档、维护文档与代码的同步，确保项目知识的可继承性

## 触发条件

- 阶段 7 完成且系统已达到交付条件
- 或用户明确要求维护/更新现有文档

---

## 8.1 技术文档汇总与架构总览

- 汇总 `/产品文档/technical/` 下所有模块文档
- 生成 `quickstart.md`：项目入口文档，链接到所有主要板块
- 生成 `architecture.md`：系统架构总览，说明模块关系与数据流
- 每个概念只保留一个"canonical home"，其余页面通过链接引用

---

## 8.2 文档增量更新（外科手术式更新）

**目标**：基于代码变更精准更新文档，避免无意义的全量重写

**执行规则**：
- 检查自上次文档更新以来的代码变更（通过 git diff）
- 建立 Docs Impact Plan：代码变更 → 影响哪些文档 → 需要怎么改
- 只修改因代码变化导致不准确/不完整的部分
- 保留现有正确内容，禁止仅做格式调整
- 若代码无实质变更，直接告知文档已是最新，不做编辑

---

## 8.3 项目根文档注入

- 检查并更新项目根目录的 `README.md`
- 确保 README 中包含技术文档入口的引用
- 若项目面向 Agent/AI 协作，可创建 `AGENTS.md`，注入标准化提示：
  ```
  本项目的技术文档位于 /产品文档/technical/ 目录。
  开始阅读：/产品文档/technical/quickstart.md
  开发时请优先查阅相关模块的技术文档，确保与最新实现一致。
  ```

---

## 8.4 文档质量检查

- 检查是否有模块缺少技术文档
- 检查 quickstart.md 是否链接到所有主要板块
- 检查文档中是否存在过期内容（与代码不一致）
- 检查是否有重复或薄页内容需要合并

## 必须输出

- 文档维护报告：更新/新增/合并了哪些文档，哪些问题已修复
- 必须询问：文档维护结果是否采纳
