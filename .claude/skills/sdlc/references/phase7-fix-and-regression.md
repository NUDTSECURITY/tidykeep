# 阶段 7：修复与回归

**角色**：软件工程师 + 测试工程师
**目标**：修复静态验证和动态功能测试中发现的问题，确保交付质量

## 触发条件

- 静态验证发现中高风险问题
- 动态功能测试有测试用例未通过

## 执行流程

1. 按严重程度排序修复问题（静态问题优先，动态测试失败次之）
2. 每修复一个问题，说明修复方案
3. 静态问题修复后，重新执行阶段 6.1-6.7 的静态验证
4. 动态测试失败修复后，重新执行阶段 6.9 的动态功能验证
5. 直到验证报告显示"建议交付：是"

## 交付条件

- 无高风险问题
- 中风险问题已全部修复或用户明确接受
- 功能符合度达到"完全符合"或"部分符合"（且偏差已被用户确认接受）
- 动态功能测试通过率达到 100%，或失败的用例已被确认为环境问题/非阻塞问题
