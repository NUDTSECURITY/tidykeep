# tidykeep 技能

本技能实现 AGENTS.md 中 tidykeep 协议的三个深度工作流。开始前先读一遍项目根目录的
`STATE.md` 与 `LEDGER.md`，并确认 `.tidykeep/config` 中的配置（扩展名清单、强制等级）。

根据用户意图选择工作流：

| 用户说 | 工作流 |
|---|---|
| "初始化 / 考古 / 第一次接入 / 给现有项目建台账" | 1. 初始化扫描 |
| "收尾 / 同步台账 / 按协议提交" | 2. 收尾同步 |
| "体检 / 审计 / 找冗余 / 清理旧代码旧文档" | 3. 体检审计 |

---

## 工作流 1：初始化扫描（一次性）

目标：为存量项目建立 STATE.md、LEDGER.md 的初始内容，并清点历史包袱。

1. **摸底**：用 `git ls-files`（非 git 仓库则遍历目录并遵守 .gitignore）列出全部受管文件
   （扩展名 ∈ config 的 CODE_EXTS ∪ DOC_EXTS，排除草稿区 .tmp/、.tidykeep/、.claude/）。
2. **填 STATE.md「当前架构与设计」**：阅读入口文件与主要模块，用 5～15 句话写清：项目做什么、
   模块划分、数据流、关键约定。只写当前有效的事实，不写历史。
3. **建 LEDGER.md 条目**：为每个受管文件生成一节（路径、最后核对=今天、TODO 空、DONE 写一行
   "初始化建档"）。文件很多（>80）时按目录分组，仅为"活跃目录"逐文件建档，其余目录先建目录级条目。
4. **清点历史包袱**，产出一张"待处理清单"表格（文件、疑点、建议、依据）：
   - 命名命中 STALE_ERE 模式的文件；
   - 未被任何地方引用的脚本：对每个候选用 grep 搜索其模块名/文件名在全仓库的引用；
   - 内容高度相似的文件对（先按文件名前缀分组，再抽样 diff 确认）；
   - 文档中与代码现状明显矛盾的段落。
5. **等待用户确认后执行**：确认删除的文件 `git rm`；确认保留的加入 `.tidykeep/allowlist`；
   每一项删除都要在 STATE.md 墓地登记（删了什么、为什么、取代者）。
6. 删除 LEDGER.md / STATE.md 里的示例节，按 Commit 规范提交，主题建议 `chore: tidykeep 初始化建档`。

**禁止**：未经用户确认就删除文件；把"可能没用"直接当"确定没用"。

## 工作流 2：收尾同步（每次任务结束）

严格执行三件事，然后自检：

1. **LEDGER.md**：本次完成项从 TODO 移入 DONE（`- [x] YYYY-MM-DD 描述`）；新发现的待办登记进
   TODO；刷新涉及文件的"最后核对"。本次新建的受管文件要新建条目；删除的文件整节移除。
2. **STATE.md**：设计/接口/架构有变 → 更新"当前架构与设计"对应段落；新增决策行（编号递增），
   把被取代的旧决策标记 `superseded → 新编号`；删除的文件登记进墓地。
3. **提交**：按 AGENTS.md 的 Commit 规范写主题 + 为什么 + 影响。
4. **自检**：`git status` 确认没有游离的临时文件；`.tmp/` 中已完成使命的验证脚本删除，
   确需保留的向用户说明原因（Stop hook 会检查残留）。
   若 pre-commit / Stop hook 拦截，按提示补全，不要用 TIDYKEEP_SKIP 静默绕过；
   确需绕过时必须向用户说明原因。

## 工作流 3：体检审计（定期）

目标：产出一份带证据的处理清单，经用户确认后执行，让仓库回到"只有当前有效内容"的状态。

1. **死文件**：对每个受管代码文件，grep 其被 import/调用情况；零引用且非入口/脚本者列为候选。
   若项目可用静态工具则交叉验证（Python: `vulture`、`deptry`；JS/TS: `knip`），
   工具不在环境里就跳过并注明"仅 grep 证据"。
2. **重复实现**：文件名相近或 LEDGER 中职责描述相近的文件对，抽样 diff，确认是否为参数级差异的副本。
3. **文档漂移**：逐一核对 docs/ 与 README 中的可验证断言（命令、路径、接口名、流程），
   与代码不符的段落列出"文档说 vs 代码是"。
4. **台账过期**：LEDGER.md 中"最后核对"距今超过 60 天的条目，逐个核对文件现状并刷新。
5. **产出报告**：表格（对象、问题、证据、建议：删除/合并/更新/加 allowlist），等待用户逐项确认。
6. **执行**：删除走 `git rm` 并登记墓地；文档当场改对；全部完成后按规范提交，
   主题建议 `chore: tidykeep 审计清理（N 项）`。
